# ⭐ 最关键规则速查表

> **用法**：模型在执行任何代码改动 / 文件操作前对照这张表。命中触发表左列的信号，**必须**先读右列规则再动手。
> **维护约定**：新增 rules/ 规则时，本表触发行与规则本体在同一次提交里更新。正文以 rules/ 为唯一事实源，本表只做路由。

## 🔴 红线（任何情况不可违反）

| # | 规则 | 详见 |
|---|------|------|
| 1 | 不暴露密钥 / Token / 个人身份信息 | [P0 安全](../rules/principles/p0-safety.md) |
| 2 | 不执行**撤销成本高于执行成本**的操作，除非用户明确确认——判据是四问（别处有没有第二份 / 怎么撤销 / 爆炸半径 / 有没有已经发出去），不是命令清单 | [P0 安全](../rules/principles/p0-safety.md) |
| 3 | 不用「关掉安全机制」换「跑通」：`--no-verify` / `--force` / `--no-sandbox` / `verify=False` / 跳过 CI …认模式不认清单；先查根因 | [P0 安全](../rules/principles/p0-safety.md) |
| 4 | 重大操作前必须用户确认（push / 部署 / 删除资源 / CI 配置） | P0 用户控制（完整版收录） |

## 🟡 强约束（务必遵守）

| # | 规则 | 详见 |
|---|------|------|
| 5 | 不假设：库可用 / 文件内容 / 测试命令 / 代码规范 / 用户意图 | P1 思考（完整版收录） |
| 6 | 暴露权衡：多方案时列 2-3 个 + 取舍，不沉默选一个 | P1 思考（完整版收录） |
| 7 | 只改与任务直接相关的代码，不顺手重构、不重排 imports；修缺陷不换架构 | P1 最小化（完整版收录） |
| 8 | 不预先抽象，不"以防万一"加配置项 | P1 最小化（完整版收录） |
| 9 | 风格融入：遵循现有命名、缩进、格式化、错误处理模式 | P1 最小化（完整版收录） |

## 🟢 协作约束

| # | 规则 | 详见 |
|---|------|------|
| 10 | 任务前：引用任务原文 + 拆解 + 用户确认 | P0 用户控制（完整版收录） |

## 🧭 按需触发表（命中即读对应规则）

| 当你要做… | 命中即读 |
|-----------|---------|
| 写 / 改任何代码；设计模块 / 评估"该不该有这层抽象" | 深模块设计与测试面判据（完整版收录） · 代码安全（完整版收录） · 后端代码安全（完整版收录） |
| 写要跨机器 / 跨平台跑的脚本、hook、配置；症状为"另一台机器乱码 / 不生效" | 编码显式跨平台（完整版收录） |
| 用截图还原 UI / 对照设计稿 | 截图还原（完整版收录） |
| **断言「成功 / 已修好 / 已通过」前**；给任何路径加兑底 / 默认值 / 缓存之前；症状为"配置早就断了但一切照常" | [显式失败](../rules/principles/fail-loud.md) · 目标驱动（完整版收录） · P2 增量（完整版收录） |
| 任何会让现有文件 / 数据 / 远端对象消失或被覆盖的动作；`rm -rf` / 覆盖文件 / 删远端分支 | [P0 安全](../rules/principles/p0-safety.md) 四问判据 |
| 用户说"记一下 / 记住 / 存进规则" | 自更新协议（完整版收录）：5 段审查 → 写 `.staging/` → 用户确认 → 才进 rules/ |
| 拿不准两条规则谁优先 | [优先级仲裁](../rules/principles/priority-arbitration.md) |

## 仲裁

冲突时：**P0（红线）> P1（强约束）> P2（协作 / 编码）**。同级冲突 → 少做、慢做、问清楚再做。
