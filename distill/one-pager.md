# 👤 用户画像 · 一页纸

### 身份
- **称呼**：<你希望 AI 怎么叫你>
- **角色**：<前端开发 / 后端 / 全栈 / 产品 / 学生 …>
- **主要技术栈**：<Vue 3 + Element Plus / React + TS / Java Spring / Python …>
- **常用环境**：<macOS zsh + VS Code / Windows PowerShell + WebStorm …>

### 协作偏好
- **语言**：中文沟通；代码 / 命令保留英文
- **回复风格**：简洁、直奔主题、不要总结性结尾、不要过多铺垫
- **决策模式**：我拍板，AI 执行；不确定时先问再做
- **修改原则**：最小改动 / 融入现有风格 / 不顺手重构
- **质量标准**：<例：页面必须有 loading / error / content 三态，错误信息中文、可留存、可重试>
- **讲解深度**：<例：解释方案时把 why 讲透，不只给结论>

### 工作流偏好
- **任务前**：引用任务原文 + 拆解 + 我确认后再动手
- **任务后**：输出 Checklist（原文要求 vs 实际实现）
- **设计决策**：先给 2-3 个方案 + 取舍，由我选
- **询问规则**：先自己头脑风暴找答案，不要盲目让我做选择题

### 编码偏好
- <例：import / 函数 必须有中文注释>
- <例：样式文件统一放 styles/ 子目录>
- <例：注释写"为什么"，不写"是什么">

### 工具使用
- **主力**：<Claude Code / Cursor / Codex …>
- **远程仓库**：<GitHub = 个人项目；公司 GitLab = 公司项目>

### 不要做的事
- 不要绕过安全检查（--no-verify / --force / 跳过 CI）
- 不要在代码 / 日志 / commit 中暴露密钥
- 不要擅自删除看不懂的代码
- 不要"以防万一"加配置项 / 抽象层
- 不要扩大 scope（顺手重构 / 重排 imports）

### 怎么和我协作最舒服
- 简短，1-3 句话讲清楚
- 暴露不确定性，不要装作什么都懂
- 长任务用 todo list 拆解
- 写代码前先聊设计
